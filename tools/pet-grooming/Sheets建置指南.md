## 帳號策略：兩個帳號、三份權限

| 角色 | 建議 Google 帳號 | 能看到的檔案 |
|---|---|---|
| **老闆**（你） | 你的個人 Gmail（例：`boss@gmail.com`） | 檔案 A ✅ + 檔案 B ✅ |
| **員工共用**（店內平板、員工電話上用） | 新開一個專用帳號（例：`shop-tablet@gmail.com`） | 檔案 A ✅（只有編輯權）／ 檔案 B ❌ |

### 兩個檔案誰建？

| 檔案 | 建在哪個帳號 | 誰能編輯 |
|---|---|---|
| **檔案 A：員工服務紀錄表** | **老闆帳號建**（你擁有所有權） | 老闆全權 + 員工帳號編輯權 |
| **檔案 B：老闆私藏報表** | **老闆帳號建**（完全不分享） | 只有老闆 |

> 🔥 **關鍵：兩份都老闆建**。如果 A 建在員工帳號，員工離職或帳號被盜 = 你的客戶資料可能被刪。老闆建 = 你永遠有所有權 + 可隨時撤回員工權限。

### 分享步驟（A 檔案建完後）
1. 在老闆帳號開檔案 A → 右上「共用」
2. 加入員工共用帳號的信箱 → 權限選「編輯者」
3. 不勾「通知」、不勾「允許他人再次分享」
4. 完成

### 店內平板怎麼設？
1. 平板上只登入員工共用帳號（**不要**登入老闆帳號）
2. 把員工快速查詢頁 + 檔案 A 都加到書籤
3. 老闆帳號完全不碰平板

## 員工快速查詢頁怎麼接這張表？

目前 `index.html` 用的是寫死的 `CUSTOMERS` 陣列（範例資料）。真正接 Google Sheets 需要兩步：

1. **在老闆帳號的檔案 A 建一個 Google Apps Script**：
   - `擴充功能 → Apps Script`
   - 寫一個 `doGet()` 函式把`客戶資料`工作表轉成 JSON 回傳
   - 部署為「網頁應用程式」→ 執行身分：我、存取權：任何人
   - 拿到一個 `https://script.google.com/macros/s/xxx/exec` 網址

2. **把 `index.html` 的 `CUSTOMERS` 換成 `fetch(那個網址)`**：
   ```js
   const res = await fetch("https://script.google.com/macros/s/xxx/exec");
   const CUSTOMERS = await res.json();
   ```

> 這一步等你先把 Sheets 建好、填十來筆真實資料測試過再做。之後跟我說「接 Apps Script」我會繼續。

### 安全流程

GitHub Pages 上的 `customer.html` 是公開檔案，任何人都可能開啟網址或看見前端程式碼。安全性不能放在前端判斷，必須由 Apps Script 後端控管。

目前安全流程如下：

1. 使用者從 LINE 選單開啟 LIFF。
2. `customer.html` 執行 `liff.init()`。
3. 若尚未登入 LINE，前端執行 `liff.login()`。
4. 登入後，前端用 `liff.getAccessToken()` 取得 LINE access token。
5. 前端呼叫 Apps Script Web App，傳送 `action=customers` 與 `token=<LINE access token>`。
6. Apps Script 用 `UrlFetchApp.fetch("https://api.line.me/v2/profile")` 向 LINE 官方驗證 token。
7. LINE 回傳真正的 `userId`。
8. Apps Script 比對 `ALLOWED_LINE_USER_IDS` 白名單。
9. 只有白名單內的 LINE userId 才回傳客戶資料。
10. 未授權帳號回傳：`此帳號未授權，請聯絡店長`。

重點：不要改回只傳 `?userId=xxx` 的版本，因為 userId 可以被偽造。必須用 LINE access token 由後端向 LINE 官方驗證。

## 2026-05-06 更新紀錄：包月客戶狀態顯示

### 為何加包月

5/6 老闆娘在散客單填到包月客（杉胖、家家），暴露包月沒有專屬流程。架構：
- 紙本：新增「包月客戶簽收單」（[generate_forms.py](../pet-grooming-receipt-form/generate_forms.py)）
- 試算表：檔案 B 新增「**包月客戶**」分頁
- 員工查詢頁：每位客戶卡片下方顯示「📅 包月中｜剩 X 次｜還有 Y 天到期」紫色 badge

### 包月分頁建置

在「寵物店儲值帳本」（檔案 B）下方新增分頁，名稱必須是 **`包月客戶`**（Code.gs 寫死的常數）。

**A1 列貼這串 header（tab 分隔）**：

```
日期	電話	客戶姓名	寵物名	服務	本次狀態	金額	已用次數	剩餘	到期日	簽名	備註
```

**設定**：
- B 欄（電話）→ 格式 → 數字 → **純文字**（避免開頭 0 被吃掉，這個坑踩過）
- A 欄（日期）+ J 欄（到期日）→ 格式 → 數字 → 日期（讓 Apps Script 的 `parseDate_()` 順利解析）

### 包月規則

- 一份包月套裝：**45 天 / 5 次**
- 客戶現場新購包月：填金額（套裝定價，例 1500），當次自動算第 1 次
- 客戶用包月扣次數：金額空白，寫第幾次（1~5）
- 第 6 次或第 46 天到期 → 包月失效，要重買

### 員工查詢頁怎麼算狀態

`Code.gs > loadMonthlyMap_()` 邏輯：
1. 掃整張包月分頁，每位客戶（電話為 key）取「**最近一筆**」當當前狀態
2. 看 H 已用次數 / I 剩餘 / J 到期日
3. 算 `daysLeft = 到期日 − 今天`
4. 判斷狀態：
   - `isActive`：未過期 + 已用 < 5 → 顯示紫色「📅 包月中｜剩 X 次｜還有 Y 天到期」
   - `daysLeft ≤ 7` 或 `remaining ≤ 1`：顯示橘色 ⚠️ 警示
   - `isExpired`：過期 → 灰色「包月已過期，用了 X/5 次」
   - `isUsedUp`：5 次用完 → 灰色「包月 5 次已用完」

漏填關鍵欄位（已用 / 剩餘 / 到期日）的列會被跳過，不顯示 badge（避免誤導）。

### Quick filter

新增「📅 包月中」chip，按下只顯示 `isActive` 的客戶。

### 部署步驟

1. 在「寵物店儲值帳本」開好「包月客戶」分頁 + 貼 header（同上）
2. Apps Script 編輯器貼新版 `Code.gs` → 儲存
3. 跑一次 `selfCheck()`，看 Logger 印出「✓ 檔案 B（包月客戶）」+ 列數
4. 編輯目前部署 → 新增版本 → 部署
5. 從 LINE 重新開員工查詢頁，看包月客戶卡片有沒有紫色 badge

### 客戶儲值 LIFF 不顯示包月

包月狀態**只在員工查詢頁**顯示，客戶端的 `pet-grooming-credit-liff` 不會看到。理由：客戶儲值 LIFF 是給客戶自己看儲值餘額的，包月是另一種模式，避免介面混淆。

## 2026-06-12 更新紀錄：多卡別支援（洗澡卡 / 剪毛卡 / 任意次卡）

### 為何加多卡別

原本包月寫死「45 天 / 5 次 / $1,500」一種套裝（`MONTHLY_PACKAGE_*` 常數）。店家想加第二種卡（例：剪毛卡買 5 送 2）就得改 code。6/12 起把「卡別」做成資料：**加品項 = 在試算表填一列，不用動程式**。

### 「卡別設定」分頁建置（選用）

在「寵物店儲值帳本」（檔案 B）新增分頁，名稱必須是 **`卡別設定`**（Code.gs 常數 `SHEET_CARD_TYPES`）。

**A1 列貼這串 header（tab 分隔）**：

```
卡名	價格	含次數	期限天數	適用服務	顯示順序	啟用
```

**範例資料**：

```
洗澡卡	1500	5	45	洗澡	1
剪毛卡	4000	7	90	剪毛	2
```

**規則**：
- **沒有這個分頁 = 單卡模式**，行為與 5/6 版完全相同（用 code 內預設常數），舊店家零改動
- 「啟用」欄空白視為啟用；填 `否/no/0/x` 等代表停用（停售但舊卡仍可扣次）
- 第一列（顯示順序最小）= **預設卡**：舊資料、沒帶卡別的請求都算它
- 卡名一旦有客戶購買就**不要改名**（改名後舊紀錄會對不上，視同另一張新卡）

### 「包月客戶」分頁加 M 欄

在原 12 欄之後加第 13 欄 header：**`卡別`**。
- 舊資料列 M 欄空白 → 自動視為預設卡，不用回填
- LIFF 結單會自動寫入卡名；手工 KEY IN 時記得填

### 行為變化

- `loadMonthlyMap_()` 改為「每位客戶 × 每張卡」各取最新一筆 → 同一客戶可同時持有洗澡卡＋剪毛卡，badge 各顯示一條
- `submitMonthly_()` 接受 `cardType` 參數；新購的次數/天數從卡別定義來；扣次以「上一筆剩餘 −1」為準（不再用全域常數回推）
